# Fiber Copy Editor

## Task Routing

| Task Type | Go To | Description |
|-----------|-------|-------------|
| Intake a new piece | `stages/01-intake/CONTEXT.md` | Build the brief: format, goal, audience profile, scope block |
| Audience-fit gate | `stages/02-audience-fit/CONTEXT.md` | Right reader, right register, right funnel stage |
| Claims pass | `stages/03-claims/CONTEXT.md` | Claim specificity, V-B-F, competitor paste test |
| Proof pass | `stages/04-proof/CONTEXT.md` | Evidence adjacent to claims, fact-registry consistency |
| Differentiation pass | `stages/05-differentiation/CONTEXT.md` | Ownable vs. generic positioning |
| Structure pass | `stages/06-structure/CONTEXT.md` | Stakes -> proof -> offer -> CTA ordering |
| CTA pass | `stages/07-cta/CONTEXT.md` | CTA matched to temperature and decision role |
| Build & curate the feedback sheet | `stages/08-feedback/CONTEXT.md` | Triage the sheet into edit letter + notes + LOC batch (HOCs capped per `shared/concern-definitions.md`); the writer accepts / edits / redirects |

## Shared Resources

Boundary rule: `shared/` is the editorial method -- stable across deployments of this template; `brand-vault/` is brand instance data -- wholly replaced at setup. This is the single home for that rule.

| Resource | Location | Role |
|----------|----------|------|
| Shared context | `shared/CONTEXT.md` | Cross-stage editorial method (inventory + usage rules) |
| Brand vault | `brand-vault/CONTEXT.md` | Voice and brand instance data |
| Setup | `setup/questionnaire.md` | Onboarding questionnaire (placeholder fill) |
